Role catalog

Every package, explained

Explore the baseline, platform layers, and each role independently. Every tool includes its purpose in this setup, alternatives worth considering, and a link to the upstream project. Alternatives are informational only and are not installed.

Required packages are part of the minimum contract. Optional packages are attempted when available and may be skipped without making the bootstrap unusable.

Managed surface

Everything this repository manages

This inventory combines package installation and configuration ownership. It includes software installed by Homebrew or role manifests, shell and application configuration deployed with Stow, and private repository configuration that is intentionally not published.

Trust boundary

Public first. Private only after authentication.

The public checkout lives at ~/.local/share/xtreemze/dotfiles-public. The private checkout keeps the canonical ~/.dotfiles path and is never fetched until GitHub CLI confirms access.

  1. 1
    Public bootstrapClone safe repository and install baseline packages.
  2. 2
    GitHub CLIInstall gh if missing and reuse existing auth where possible.
  3. 3
    Local authenticationRun gh auth login; no token is stored in this repository.
  4. 4
    Access checkVerify the account can read xtreemze/.dotfiles.
  5. 5
    Private handoffAuthorized machines clone private configuration into ~/.dotfiles.
  6. 6
    Safe fallbackWithout private access, apply only the audited public Stow packages.

Exposure policy

What is safe to publish

Public

Bootstrap logic, package metadata, documentation, role plans, and explicitly audited path-agnostic configuration.

Private

Machine metadata, personal Git identity, SSH material, auth state, secrets, service credentials, private helpers, and configuration that still assumes private paths.

Fail closed

The publication pipeline uses an allowlist, rejects symlinks, scans for high-risk secret patterns, and validates shell entrypoints before Pages deploys.
